## Approved task-specific deviation — `pmOnFail: ignore`

- **Approval:** Project Owner approved for M1-T01 only on 2026-10-19 ("DEAZLY — Fix M1-T01 Review Findings"). Full detail: [[09-Implementation/M1-T01-Scope-Proposal]] § 9.
- **Root cause:** pnpm 12.14.0 resolves the root `packageManager` field as a config dependency; the approved `--offline` install failed (`ERR_PNPM_BAD_CONFIG_DEP`) and `--frozen-lockfile` failed (`ERR_PNPM_FROZEN_LOCKFILE_WITH_OUTDATED_LOCKFILE`).
- **Fix:** one setting `pmOnFail: ignore` in `pnpm-workspace.yaml` — the pnpm 11+ replacement for `managePackageManagerVersions: false`, and the only value that avoids the lockfile env document.
- **Tradeoff:** pnpm no longer self-downloads or self-verifies the pinned version. The pin is not weakened: `packageManager`, `engines` and `.node-version` remain, and the workspace test asserts them.
- **Required external checks:** `node --version` = `v24.22.0` and `pnpm --version` = `12.14.0` before workspace commands (see README).
- **Independent verification:** Codex reproduced the failure and the fix in an isolated workspace, confirmed the setting is supported, re-ran the offline/frozen workflow (13/13 tests pass) and observed an unchanged lockfile hash across frozen runs.
- **Boundary:** a task-specific exception only; it authorizes no other task and no further configuration change.
